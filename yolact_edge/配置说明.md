# YolactEdge Windows 配置说明

本文档基于一次完整的 Windows 部署过程整理，目标是让遇到相同问题的用户可以少踩坑，尽快把项目跑起来。

适用目标：

- 在 Windows 上完成 `yolact_edge` 的环境配置
- 成功编译 `pycocotools` 与 `cython_nms`
- 成功运行单图推理
- 默认先走 `--disable_tensorrt` 路线

## 1. 已验证环境

以下组合已经在本仓库中验证通过：

- Windows 10/11
- Python `3.8.15`
- Miniconda 自带 Python
- Visual Studio 2022 Community / Build Tools
- MSVC 编译器可用，`cl` 命令正常
- PyTorch `1.8.1+cu111`
- TorchVision `0.9.1+cu111`
- NVIDIA RTX 3050 Ti Laptop GPU

不建议直接使用：

- Python `3.14`
- PyTorch `1.6.0+cu101` 搭配 Ampere 显卡

原因：

- 本项目代码和依赖较旧，`Python 3.14` 兼容性差
- `torch 1.6.0+cu101` 不支持 `sm_86`，会对 RTX 3050 Ti / RTX 30 系显卡报不兼容警告

## 2. 仓库中的必要修复

为了让 Windows 下 `cython_nms` 正常编译，当前仓库的 [setup.py](./setup.py) 已补充 NumPy 头文件路径：

```python
import numpy as np
Extension("cython_nms", ["yolact_edge/utils/cython_nms.pyx"], include_dirs=[np.get_include()])
```

如果你使用的是原始仓库且在 `pip install .` 时遇到：

```text
fatal error C1083: 无法打开包括文件: “numpy/arrayobject.h”
```

请先确认 `setup.py` 中是否包含这项修复。

## 3. Python 环境创建

### 3.1 不要依赖 `py -3.8`

如果系统没有安装 `py` 启动器，执行：

```powershell
py -3.8 -m venv .venv38
```

可能会报：

```text
No suitable Python runtime found
```

这种情况说明：

- 你机器上可能只有 Conda/Miniconda 的 Python
- 但没有被 `py` 启动器注册

可直接用已有的 Miniconda Python 创建虚拟环境：

```powershell
C:\Users\你的用户名\miniconda3\python.exe -m venv .venv38
```

验证：

```powershell
.\.venv38\Scripts\python.exe -V
```

## 4. 加载 Visual Studio 编译环境

本项目在 Windows 下需要编译：

- `pycocotools._mask`
- `cython_nms`

所以必须让 `cl` 命令可用。

### 4.1 判断是否已加载成功

```powershell
cl
```

如果输出类似：

```text
Microsoft (R) C/C++ Optimizing Compiler Version ...
```

说明编译环境已就绪。

### 4.2 如果 `cl` 不存在

需要先在 PowerShell 中加载 VS 开发环境。可参考：

```powershell
& "E:\visual studio\Microsoft Visual Studio\18\Community\Common7\Tools\Launch-VsDevShell.ps1" -Arch amd64 -HostArch amd64
cl
```

如果你的 Visual Studio 不在这个路径，请按实际安装路径调整。

也可以用 `vswhere.exe` 查找安装目录。

## 6. 安装 pycocotools（含 YTVOS）

本项目依赖的不是普通 `pycocotools`，而是包含 `ytvos.py` / `ytvoseval.py` 的 fork：

- `https://github.com/haotian-liu/cocoapi`

### 6.1 直接从 GitHub 安装可能遇到的问题

在 Windows + MSVC 下，原始 `setup.py` 中的 GCC 参数可能导致报错：

```text
cl: 命令行 error D8021 :无效的数值参数“/Wno-cpp”
```

这是因为 `setup.py` 中存在只适用于 GCC/Clang 的参数，例如：

```python
extra_compile_args=['-Wno-cpp', '-Wno-unused-function', '-std=c99']
```

### 6.2 推荐处理方式

1. 克隆 fork 到本地
2. 修改 `PythonAPI/setup.py`
3. 去掉上述 GCC 参数
4. 从本地安装

示例流程：

```powershell
git clone https://github.com/haotian-liu/cocoapi.git D:\cocoapi
cd D:\cocoapi\PythonAPI
```

把 `setup.py` 中的：

```python
extra_compile_args=['-Wno-cpp', '-Wno-unused-function', '-std=c99']
```

改成：

```python
extra_compile_args=[]
```

然后安装：

```powershell
& "D:\All Program\yolact_edge\.venv38\Scripts\python.exe" -m pip install .
```

验证：

```powershell
& "D:\All Program\yolact_edge\.venv38\Scripts\python.exe" -c "from pycocotools.coco import COCO; print('COCO ok')"
& "D:\All Program\yolact_edge\.venv38\Scripts\python.exe" -c "from pycocotools.ytvos import YTVOS; print('YTVOS ok')"
```

## 7. 安装 yolact_edge

在项目根目录执行：

```powershell
& "D:\All Program\yolact_edge\.venv38\Scripts\python.exe" -m pip install .
```

验证：

```powershell
& "D:\All Program\yolact_edge\.venv38\Scripts\python.exe" -c "import yolact_edge; print('yolact_edge ok')"
```

## 10. Windows 常见问题

### 10.1 `No suitable Python runtime found`

原因：

- 没有安装 `py` 启动器
- 只有 Conda Python，没有标准 Python Launcher

解决：

- 直接用 `miniconda3\python.exe -m venv .venv38`

### 10.2 `SSLEOFError` / pip HTTPS 失败

常见原因：

- VPN
- 代理
- 安全软件拦截 HTTPS

解决：

- 关闭 VPN 后重试
- 切换镜像源
- 直接使用 `https://pypi.org/simple`

### 10.3 `cl` 无法识别

原因：

- Visual Studio 已安装，但当前 shell 没有加载开发环境

解决：

- 使用 `Launch-VsDevShell.ps1`
- 或打开 `Developer PowerShell for VS`

### 10.4 `invalid numeric argument /Wno-cpp`

原因：

- `pycocotools` fork 的 `setup.py` 含 GCC 参数

解决：

- 删除 `extra_compile_args` 中的 GCC 参数

### 10.5 `numpy/arrayobject.h: No such file or directory`

原因：

- 本仓库 `setup.py` 未传入 NumPy 头文件目录

解决：

- 确认 `setup.py` 中的 `Extension(... include_dirs=[np.get_include()])` 已存在

### 10.6 `sm_86 is not compatible with the current PyTorch installation`

原因：

- 使用了过旧的 PyTorch，如 `1.6.0+cu101`

解决：

- 改为 `torch 1.8.1+cu111` 和 `torchvision 0.9.1+cu111`

### 10.7 `cv2.imread(...)` 返回 `None`

原因：

- `--image` 指定的文件不存在
- 路径错误

解决：

- 先确认图片文件存在
- 优先使用项目目录下的相对路径

### 10.8 Windows 盘符与 `input:output` 参数冲突

本项目在以下参数中使用 `:` 分隔输入输出：

- `--image=input.jpg:output.jpg`
- `--images=input_dir:output_dir`
- `--video=input.mp4:output.mp4`

但 Windows 绝对路径本身也包含 `:`，例如 `C:\...`。

因此不建议这样写：

```powershell
--image=C:\a.jpg:D:\b.jpg
```

建议：

- 把输入输出文件都放到当前项目目录
- 使用相对路径，例如：

```powershell
--image=input.jpg:output.jpg
```

## 11. 推荐的最低可用流程

如果你的目标只是“先在 Windows 上跑通一张图”，最短路径如下：

1. 用 Python 3.8 创建 `.venv38`
2. 加载 VS 开发环境，确保 `cl` 可用
3. 安装 `torch 1.8.1+cu111`
4. 安装常规依赖
5. 本地修补并安装 `haotian-liu/cocoapi`
6. 执行 `pip install .`
7. 下载 `weights\yolact_edge_54_800000.pth`
8. 用 `--disable_tensorrt` 跑 `eval.py`

## 12. 补充说明

- Windows 下优先先跑 `--disable_tensorrt`
- TensorRT 路线更偏 Linux / Jetson，不建议作为 Windows 首次部署目标
- 如果只是做单图/视频推理，先不要引入额外复杂度
